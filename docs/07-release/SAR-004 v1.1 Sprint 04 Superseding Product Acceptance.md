## 6. PDR-004-001 Faithfulness

S4-010 implements the locked policy faithfully:

1. `increase` uses `actual >= target`; `decrease` uses `actual <= target`; `maintain` uses the inclusive `target ± absolute tolerance` interval; `binary` uses exact Boolean equality.
2. Canonical decimal values and integer-backed comparison prevent display rounding from changing a decision.
3. Deadline evaluation uses the final instant of the target date in its snapshotted IANA time zone.
4. `effectiveAt` determines evidence timing and `recordedAt` preserves when DeliveryIQ learned of it.
5. Late satisfying evidence may restore `target_met` without erasing the missed-deadline fact; later regression may restore `tracking` or `target_not_met` without erasing prior history.
6. Corrections append same-scope, single-branch, acyclic superseding observations; only deterministic terminal leaves participate.
7. Measure definitions, observations and status events are immutable or append-only as required.
8. Customer and executive projections use controlled status/reason copy and do not imply causation.
9. Tenant, permission, idempotency, concurrency, trace, export and reporting controls are covered by the filed tests and managed schema evidence.
10. Every mandatory PDR-004-001 Section 10 fixture executes by its exact stable ID.

No amendment to PDR-004-001 is required for S4-010.

## 7. Recorded Limitations

### L-004-01 — Genuine eligible Delivery DNA journey unavailable

**Classification: accepted Sprint limitation; general-availability blocker.**

The platform contains no genuine eligible Delivery DNA portfolio from which to exercise the complete customer journey. This does not reopen the accepted Sprint 04 deterministic implementation and does not justify synthetic customer evidence. It blocks general availability and customer enablement of the complete Delivery DNA-to-recommendation journey until a separately authorised valid collection journey passes end to end.

### L-004-02 — Inherited repository-wide lint debt

**Classification: accepted inherited debt; not a Sprint 04 release blocker.**

The 613 inherited errors and 15 warnings remain outside changed scope. Changed-file lint/format, type checking and production build pass. The inherited baseline must not increase and must not be described as a clean repository-wide lint result.

### L-004-03 — Authorised audit export not exercised live

**Classification: accepted contained limitation; audit-export enablement blocker.**

The export implementation, allow-list, integrity gate, redaction, expiry, rate limit, access logging and failure paths pass automated and source-contract verification. Production has no genuine portfolio or action, no customer evidence was manufactured, and `audit_exports` remains disabled. The live export test is therefore not required to manufacture data for Sprint review, but it is required before the capability is enabled for any customer. The feature must remain deny-by-default until an authorised genuine portfolio can exercise export, redaction, expiry and access logging.

### L-004-04 — Tier 1 recovery cannot be demonstrated on current platform capability

**Classification: not an accepted limitation; Product/architecture decision and release blocker.**

PDR-004-001 requires Tier 1 RPO <=15 minutes, Tier 1 RTO <=4 hours and an isolated, measured recovery rehearsal. Lovable's documented self-service control provides one daily in-place database backup retained for roughly 14 days, not arbitrary point-in-time recovery. The documented project-data export is limited to one request per 24 hours and is not an isolated managed restore. No self-service isolated target or qualifying recovery-point identifier is documented.

The [S4-014 recovery record](../sprint-04/S4-014-recovery-rehearsal.md) correctly reports this as **BLOCKED — EXTERNAL PLATFORM CAPABILITY**. Automated state-machine tests, an HTTP smoke test, an in-place daily snapshot and a logical export must not be represented as a Tier 1 recovery rehearsal. This limitation directly leaves PB-004 S4-014 AC4, S4-014 AC6 and the release checklist open.

Authoritative platform references: [Lovable database backup and restore](https://docs.lovable.dev/features/database#backup-and-restore) and [Lovable Cloud data export](https://docs.lovable.dev/features/advanced-settings#export-lovable-cloud-data).
