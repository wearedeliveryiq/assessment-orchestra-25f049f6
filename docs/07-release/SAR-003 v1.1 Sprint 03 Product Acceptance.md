## 4. Snapshot restart decision

The **Start a new Snapshot** action is accepted as a safe, reversible UX completion within the approved Snapshot journey. It creates a new opaque anonymous session, preserves the earlier completed Snapshot and linked assessment, reuses the existing privacy/retention/abuse controls and creates no analysis activity.

This does not change a locked product rule and therefore does not require a PDR amendment. PR #38 and the additional regression test are sufficient lean evidence.

## 5. Defect and migration review

The first continuation attempt failed because an integer response was supplied to a JSONB column. The operation failed atomically: no partial draft, response or link was committed. The defect was corrected through a forward migration using JSONB serialisation while preserving least-privilege grants and migration history.

This is an ordinary corrected implementation defect, not a product-rule conflict or release blocker. The successful retry created the exact 13-response draft and the regression is covered by tests.

### L-003-01 — Inherited repository-wide lint debt

The limitation from SAR-003 v1.0 remains accepted. Changed files pass targeted lint/format, the build and relevant regression suite pass, and the change does not worsen the inherited baseline.

### L-003-03 — First action-entitlement production smoke outstanding

No genuine customer currently holds `delivery_dna_action` version `1.0.0`; engineering correctly did not manufacture a customer entitlement. Automated entitlement, permission, expiry/revocation, tenant-isolation, immutable-result and paid-read/write coverage passes.

This does not block the Snapshot, complete free result or current unavailable commercial state. Before `delivery_dna_action` is first offered or granted to a customer, an authorised test or customer tenant must verify:

1. the entitled projection reveals the same immutable result and run without recalculation;
2. one permitted decision/action/outcome write succeeds and remains tenant scoped;
3. an unentitled or unauthorised read and mutation remain denied without leakage; and
4. removing or expiring entitlement removes paid access without deleting history.

Record this evidence in the existing implementation report or release record. Do not create a new governance package.
